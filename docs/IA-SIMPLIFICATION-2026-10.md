## 1. 业务定义：先决定哪些事值得占页面

### 服务对象与价值

- **主要用户**：两人或多人共同照顾宠物的家庭、伴侣和室友；也覆盖长期用药或需要临时交接的照护者。
- **核心价值**：不用靠记忆管理宠物照护；家里人能马上看清今天该做什么、谁在负责、最近发生了什么。
- **本次要解决的问题**：完成同一件业务时入口不唯一；宠物、家庭、记录、设置之间互相跳；对象详情像导航枢纽一样不断把用户送进新页面；表单和低频治理能力被当作同级页面。

### 业务对象

`User → Family membership / role → Pet → Care Plan → Rule → Occurrence → Pet Event`

请求与交班附着在原 Occurrence 上；分享、趋势、用量、通知属于上述业务的从属读面或管理能力，不另造一条主业务线。Family 是共享、角色与照护计划的上下文；Pet 是独立资产；All / Family / Pet 只是展示范围，不是新的业务对象。

### 主闭环与当前承载

| 环节 | 用户动作与结果 | 当前承载 | 状态 |
|---|---|---|---|
| 建立照护上下文 | 建立/加入家庭，添加宠物并确定成员权限 | 家庭列表、家庭详情、表单、激活流程 | 已实现 |
| 安排照护 | 为家庭中的宠物建立计划、规则和负责人 | 宠物详情、照护页、计划表单、指派页 | 已实现 |
| 执行今天事项 | 查看今天清单并完成、跳过、调整或转交 | Today、请求中心、请求/交班详情 | 已实现 |
| 沉淀事实 | 执行结果进入宠物时间线；补记健康事件 | 时间线、记录详情、记录表单 | 已实现 |
| 继续照护 | 根据历史与到期状态回看并安排下一次 | Today、宠物工作区、时间线 | 已实现 |

闭环一句话：**家庭为宠物安排照护 → 照护者在今天执行或交接 → 结果作为宠物事实留存 → 再据此继续照护。**

### 明确不做

- 不增加第六个主导航入口。
- 不拆出独立的通知、分享、趋势、用量主业务。
- 不为“路由数字更小”牺牲家庭治理、多家庭选择、宠物资产治理或关键恢复路径。
- 订阅已上线(R-20261013-1):paywall 是升级动线页,不是核心页也不是要移除的页;额度受限页给「整理/升级」双动作,不送死路。依据:[PRODUCT.md §5(2026-10-19 已校正)](PRODUCT.md)。

### 额度与付费边界

额度规则不因 IA 调整而改变：free 档额度与唯一用量页面以 [PRODUCT.md §5.0](PRODUCT.md) 为准。超额只阻止新增写入，既有数据仍可读、编辑、删除和导出。账户用量作为 More → Account 下的辅助子页；错误提示就近提供解决动作，不把用户送进无购买能力的升级死路。

### 可判定验收目标

- Given 用户要完成一个既有业务，When 从主导航进入，Then 只有一个规范入口；集合页之间没有同一业务的横向入口。
- Given 用户打开对象详情，When 找到主任务，Then 主 CTA 唯一；页面内直达出口不超过 4 个，其余同对象低频治理动作进入“更多操作”。
- Given 用户在表单或动作子页，When 保存成功或取消，Then 回到明确的父对象；失败保留输入并能重试；系统深链没有来源时提供确定的父级返回。
- Given 用户从家庭打开宠物，When 看完宠物后返回，Then 回到原家庭；从全局宠物列表进入则回宠物列表，不出现家庭↔宠物列表循环。
- Given 用户需要完成核心闭环，When 沿唯一主路径操作，Then 从主入口到结果不超过 3 个页面层级（sheet/dialog 不算页面层级）；复杂表单可占一个子页。
- Given free 用户撞到额度，When 查看阻断说明，Then 不出现购买 CTA，且有至少一个可执行的管理或恢复动作。

## 2. 当前结构核查与问题定位

### 证据口径

- 当前 `APP/app` 有 **37 个 `.tsx` 路由文件**：其中 5 个主 Tab，2 个 layout，另含启动分流、登录、公开邀请/分享、对象页、表单和管理页。文件数不等于主入口数。
- 当前五 Tab 为 **今天、时间线、请求、宠物、更多**，以 `APP/app/(tabs)/_layout.tsx` 为准。
- 导航调用扫描覆盖 `APP/app` 与 `APP/src` 下 `router.push/replace`、`href`、`Link`、`navigate`。家庭、宠物之间确有双向入口：家庭详情可进宠物详情；宠物家庭关联可回家庭详情；家庭详情也可回 Today/时间线；通知、用量、设置等恢复路径会回家庭列表。
- **量化实锤(78 条跳转边全量扫描)**:家庭类页面入边 19、宠物类 16;宠物详情 9 出口、家庭详情 8 出口;最深链 Pets→宠物详情→照护→指派=4 层;`/families` 列表 10 个直达入口。
- 现有 [APP-PAGE-MAP.md](APP-PAGE-MAP.md) 与本轮用户描述存在落差：地图规定主入口和层级，但目前详情页导航出口仍多，且存在照护指派独立深层路由。

### 造成“死循环”的具体结构

1. **入口分散**：宠物/家庭创建和家庭管理可从 Today、Pets、More、用量、设置及错误恢复路径进入。用户无法判断哪个才是该业务的家。
2. **集合页互相引流**：Families 列表 ↔ Pets 列表、家庭详情 ↔ 宠物详情容易变成“看完一个又被送到另一个”的横向浏览。
3. **详情页变成菜单**：宠物详情承载档案、照护、转移、就医摘要、家庭等大量出口；家庭详情也同时导向宠物、时间线、Today、邀请、转移、通知和额度处理。
4. **管理动作继续下钻**：宠物 → 照护 → 计划负责人指派，形成核心闭环之外的额外页面层。
5. **路由数量掩盖层级问题**：登录、公开分享和表单路由不应与五个常驻入口同级比较；优先治理入口重复和路径深度，随后再裁撤确实可合并的路由。

## 3. 目标信息架构

```text
五个常驻核心页（唯一一级入口）
├─ 今天：执行今天事项；原位完成、跳过、撤销、安排责任
├─ 请求：处理待回应请求与交班；查看单条责任链
├─ 时间线：查看事实；新增事实；打开记录详情
├─ 宠物：浏览宠物；进入宠物工作区
└─ 更多：家庭治理入口、账户、设置、趋势、反馈

对象工作区（回答“这个对象现在怎样”）
├─ 宠物：档案 / 照护；家庭关联留作上下文，不作为跨列表导航
├─ 家庭：成员与权限 / 共享宠物 / 家庭设置
├─ 请求：一条请求或一个交班批次
└─ 记录：一条宠物事实

动作子页（完成一件事，成功/取消后回父对象）
├─ 创建/编辑宠物、家庭、计划
├─ 家庭加入、邀请、成员管理
├─ 宠物/家庭转移
├─ 计划负责人调整
└─ 通知、账户、用量等低频管理

系统/公开路由（不进入主导航）
登录、启动分流、激活/邀请、匿名分享、深链详情
```

**分层定义**：核心页是五个 Tab；对象页是从其唯一所属 Tab 进入的上下文；动作表单是该对象的子页。公开分享、登录和激活是系统入口，不计入日常导航。任何业务最多经过“主 Tab → 对象/集合 → 动作子页”三层。

## 5. 唯一入口图与返回规则

| 业务 | 唯一入口 | 次级对象 | 完成后 |
|---|---|---|---|
| 今天执行/快速补记 | Today | 请求详情或记录编辑器 | 回 Today 原事项/范围 |
| 请求回应/交班 | Requests 或原事项责任卡 | 请求/交班详情 | 回 Requests 或原事项 |
| 浏览/维护宠物 | Pets | 宠物工作区 | 回 Pets 列表 |
| 建立/治理家庭 | More → 家庭管理选择器 sheet | 家庭详情 | 回家庭详情或 More |
| 查看/维护事实 | Timeline | 记录详情/事实表单 | 回原 Timeline 范围 |
| 账户与个人设置 | More | Account / Settings | 回 More |
| 用量 | More → Account → Usage | 用量明细 sheet（若已存在） | 回 Account |
| 外部照护信息 | 宠物工作区对应分享区 | 公开只读链接 | 关闭/撤销后回宠物 |

规则：

1. 同一写动作只在所属对象出现一个主入口；Today 的“添加宠物”引导只在无数据冷启动或明确阻断时出现，并替代 Pets 主入口的空态 CTA。家庭创建/加入的日常入口只在 More 的家庭管理 sheet。
2. 不允许集合页相互跳转：Pets 列表不放 Families 列表入口；家庭选择 sheet 不放 Pets 列表入口。对象之间只允许必要的上下文引用，并通过 `replace`/父级返回保留来源。
3. 对象详情首屏只呈现身份、当前状态、一个主操作；同对象的低频治理动作收进明确的“更多操作”分组，危险动作置底。
4. 返回不猜来源：页面内导航携带稳定父级；外部通知/分享等无历史栈时使用固定 fallback。保存、取消、失败重试都留在所属业务流。
5. 表单是明确的动作子页，不额外套确认页、选择页、结果页；可撤销/可轻量选择的交互用原位控件或 sheet，复杂输入用独立子页。

### 硬法五条(入 verify-client-layers 守卫,违反即红)

1. **三层封顶**:主 Tab → 对象/集合 → 动作子页,任何第四层页面路径即违规(sheet/弹层不算页面层级);
2. **详情页直达出口 ≤4**,且必须属于本对象;其余动作收「更多操作」分组,危险动作置底;
3. **集合页零横向互跳**(Pets/Requests/Timeline/家庭选择器互链全禁;对象级下钻合法,replace 语义保留来源);
4. **表单单一父入口**(同一写动作全 App 只有一个主动作入口;冷启动引导 CTA 例外且只在空态);
5. **返回不猜来源**:子页携带稳定父级,深链无栈时用固定 fallback,禁止导航到集合页充当"返回"。

## 6. 页面契约摘要

| 页面 | 唯一要回答的问题 / 业务与数据 | 首屏与主操作 | 进入条件 / 权限 | 成功、失败恢复与离开 |
|---|---|---|---|---|
| Today | 今天有哪些 Occurrence 待做、由谁负责 | 当前范围与状态；主操作完成当前事项 | 已登录；数据按当前家庭权限 | 写入后原位更新；失败保留事项并重试；进入请求或返回原 Tab |
| Requests | 哪些责任请求要我回应 | 待回应优先；回应/查看详情 | 已登录；角色和请求参与关系由服务端判定 | 响应后刷新责任链；失败留在详情；返回 Requests/原事项 |
| Timeline | 宠物发生了哪些事实 | 时间范围与事实流；新增事实 | 已登录且对宠物有读取权 | 写入后回原范围；上传失败保留表单信息；详情返回原列表 |
| Pets | 有哪些宠物，当前哪只需要照护 | 活跃宠物列表；打开宠物/新建宠物 | 已登录；写操作服从 owner/editor 与额度规则 | 新建进入宠物工作区；失败留表单；返回 Pets |
| More | 账户和低频治理从哪里进入 | Account、家庭管理、Trends、Settings；主动作进入 Account 或家庭管理依状态 | 已登录 | 每个入口到唯一归属页；加载失败提供重试 |
| 宠物工作区 | 这只宠物当前档案与照护状态是什么 | 宠物身份、范围、档案/照护分区；照护计划或编辑档案按状态择一 | 可读取该宠物；写入口按权限隐藏/禁用并解释 | 动作完成回本页；权限/加载错误保留对象上下文；经父级返回 |
| More 家庭管理 sheet + `/families/[familyId]` | 选择要管理的家庭；详情回答当前家庭有哪些成员、宠物与治理状态 | sheet 负责选家/新建/加入；详情首屏显示家庭名/角色/成员/宠物，owner 主操作为邀请或治理 | 家庭成员；owner-only 动作由服务端守卫 | 选中后直接打开家庭详情；子动作回当前家庭；不跳其他集合 |
| 表单子页 | 当前创建/修改的单一对象是什么 | 仅显示本表单字段与一个提交动作 | 从唯一父级进入；权限与额度预检 | 成功回父级或新对象；失败保留草稿与可读错误；取消回父级 |

## 7. 分批落地与停止条件

### 第 0 批：先冻结唯一入口

- 页面菜单与空态 CTA 盘点，逐项写明归属页面；重复入口改成深链或移除。
- 确认每个动作的父级和返回路径；补齐来源缺失时的固定 fallback。
- 修复 Pets ↔ Families 列表互跳和对象详情的横向导流。

### 第 1 批：减出口，不改业务数据

- 瘦身宠物与家庭详情；低频操作收进对象内“更多操作”。
- `assignments` 改为照护页内负责人管理交互。
- 家庭列表从独立路由降为 More 的管理 sheet；家庭详情仍为对象页，家庭表单仍为子页。

### 第 2 批：合并真实重复页面

- Account 删除状态内联；激活照护步骤并回激活流程；UI Lab 限开发。
- paywall 入口收敛到四处升级动线(撞墙引导/More/账户/趋势);额度阻断文案保证「整理/升级」双动作可恢复。

### 第 3 批：更新规范与实测

- 同步 [APP-PAGE-MAP.md](APP-PAGE-MAP.md)、路由守卫和本方案的入口图；只保留一个现行页面规范。
- 核对主 Tab 五入口、各对象子页返回、通知深链、冷启动激活、空态创建、角色权限和额度阻断。
- 按项目宪法完成桌面与 390px 移动端逐页检查、主闭环与逆向流程真实栈走查，形成证据；未验证项明确标记，不报“完成”。

### 每批禁止越过的条件

- 家庭/宠物的多对多关系、共享权限或 owner 生命周期发生变化。
- 修改 API、数据库、schema 或删除既有业务能力。
- 合并后产生超过三层的核心路径、孤儿路由、失效通知深链或无返回路径。
- 任一核心页面缺少 loading / empty / error / success 状态或错误恢复动作。

以上情况应暂停对应批次并重新裁决方案，不用实现结果倒逼接受 IA。

## 8. 本轮结论

核心页面是五个 Tab；家庭、宠物、请求和记录详情是必要对象页；所有创建、编辑、转移和管理表单属于所属对象的子页；登录、邀请、分享和激活是系统入口；趋势、用量和设置是 More 下的辅助能力。家庭选择/列表不再占独立导航页，而是 More 内的管理 sheet，选中后直达对应家庭。

精简的着力点不是把每个子页都塞回一个大页面，而是让每种业务只有一个家、详情页不做导航枢纽、表单结束明确回父级，并移除确实没有独立业务价值的管理路由。方案确认前，本轮不更改实际导航、界面或路由实现。
