# PLANET App — 视觉与迁移说明

状态：2026-09-10

## 视觉基准（冻结）

原生 App 的视觉、布局、交互以 **`mobile-v3`（Web）为唯一冻结基准**。移动端与 Web 宽屏都使用同一组五项主入口（今天、请求、宠物、记录、更多）；Web 以侧栏呈现，移动端以底栏呈现，不能因为平台不同而增加第二套业务导航。

- 路径：`../mobile-v3/`
- 规则：**不要改 `mobile-v3`**。迁移期只读对照。

## 当前实现

- Theme tokens（对齐 v3 `:root`）
- 基础控件：`AppText` / `Button` / `TextField` / `Screen` / `Card` / `MoreGroup` / `MoreRow`
- 悬浮底栏（今天 / 请求 / 宠物 / 记录 / 更多）；家庭管理从更多或桌面侧栏进入
- 邮箱验证码登录
- 今天：拉取 `/today`、完成 / 跳过 / 撤销 / 协作转交 / 排程例外
- 家庭、宠物工作区、用药、权限、转移、分享、趋势和设置
- 宠物页：每只活跃宠物以照护卡呈现身份、今日待做数量、关联家庭和下一项；归档档案单独降级展示
- 家庭详情：家庭总览、今日安排、默认负责人、成员权限和宠物列表在同一上下文；每只宠物直接显示今天状态；负责人卡读取正式责任视图
- 请求中心、单项/批量责任链、通知动作和离线顺序同步
- 请求中心固定显示待回应、我发出、批量安排三类真实状态，空状态也保留可判断的信息结构
- 时间线：记录流、照片、编辑/删除权限、照护事实回链 Today
- 桌面侧栏：五个主入口、家庭管理、账户与安全

## 后续施工顺序

1. 在可操作的 iOS Simulator / Android Emulator 完成通知动作、断网恢复和长文案验收；实体设备只有明确授权时才使用。
2. 对 Today、宠物工作区、家庭详情、记录页做同一轮视觉收束；页面只保留一个主叙事和一个主动作。
3. 补齐 Android 与 Web 的关键交互差异，并为核心状态保留可复现的验收路径。

## 原则

1. Token：从 `mobile-v3/src/styles.css` 抽取到 `APP/src/ui/theme`
2. 组件：对照 v3 结构用 RN 重写，不搬 DOM/CSS
3. 业务：`planet-api` + React Query
4. 平台：先 iOS；Android 同仓补差异
5. **交互与信息架构：以 [UX-SPEC.md](./UX-SPEC.md) 为准**（方法论、每页规格、动效语义）
