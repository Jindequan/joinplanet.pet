# PLANET APP Design System

版本：1.0
适用范围：`mobile-v2` 的 iOS / Android 原生 APP
状态：工程约束基线

这份规范是所有页面、组件、交互、布局和视觉实现的共同约束。视觉示例不是实现源；实现必须通过 React Native 的主题 token、共享组件和导航能力完成。

## 1. 产品原则

### 1.1 温暖，但不幼稚

使用柔和背景、适度圆角、清晰留白和克制的插画/图标。避免儿童化 emoji、过度渐变、装饰性噪音和无意义动画。

### 1.2 先行动，再记录

用户打开页面后，应能立即知道“现在要做什么”。主要操作必须明确、可触达、可恢复；历史、统计和说明服务于行动，而不是压过行动。

### 1.3 共享清晰，边界明确

Pet 是信息主体，Family 是共享关系；顶部的 All / Family / Pet 只是展示过滤器。任何页面都必须清楚说明当前对象、可见范围和操作影响。

### 1.4 低认知负担

一页只服务一个主要任务。每个页面只有一个主标题和一个主要 CTA；次要操作降级为次按钮、文本按钮或菜单。

### 1.5 可逆、可解释、可恢复

完成、归档、删除、退出共享等操作必须有明确反馈。破坏性操作必须二次确认或提供撤销；网络失败不能静默丢失用户输入。

### 1.6 不依赖颜色传达唯一含义

状态必须同时使用文字、图标、形状或布局表达。颜色只负责加强识别，不能作为唯一依据。

## 2. 唯一实现来源

```text
mobile-v2/src/ui/theme/tokens.ts       颜色、间距、字号、圆角、动效、布局 token
mobile-v2/src/ui/components/            可复用交互组件
mobile-v2/src/ui/navigation/            导航与安全区
mobile-v2/app/                          页面组合和业务状态
```

HTML 设计文档仅用于展示和评审，不能复制 CSS 到 APP，也不能绕过共享组件直接写一套页面样式。

规则：

- 新页面必须使用 `Screen`、`AppText`、`Card`、`Button`、`TextField` 等共享组件。
- 新颜色、字号、间距、圆角、阴影必须先进入 `tokens.ts`。
- 页面样式只能组合 token，不得新增散落的品牌色和魔法数字。
- 例外必须写明原因，并限制在组件内部；页面不得自行建立第二套设计系统。

## 3. 视觉基础

### 3.1 色彩层级

- `background`：页面底色，保持安静、低对比。
- `surface`：卡片、输入框、Sheet 的内容底色。
- `surfaceRaised`：需要从背景中被看见的轻层级区域。
- `text`：正文和标题。
- `textMuted`：辅助说明、次要信息。
- `textSubtle`：placeholder 和弱提示，不得承载关键内容。
- `brand`：品牌识别、选中态、非正文图标。
- `brandStrong`：正文链接、主要图标和需要满足对比度的品牌文字。
- `success / warning / danger`：状态语义，必须配合文字或图标。

正文文字目标对比度至少 4.5:1，大字号至少 3:1；小字号徽章、按钮文字和输入提示不得使用未经验证的浅色 token。

### 3.2 字体

统一使用系统字体；字号只能使用 `tokens.ts` 中的 typography variant：

- `display`：欢迎页或极少数品牌主标题。
- `title`：页面标题。
- `heading`：卡片标题、区块标题。
- `body`：正文和重要信息。
- `label`：按钮、表单标签、短操作文字。
- `caption`：辅助信息、时间、来源和状态说明。

正文默认 16 / 24。重要信息不能只放在 caption 中。所有文字必须允许系统字体放大，禁止固定高度裁切文本。

### 3.3 间距与布局

采用 4pt 基础网格，页面默认水平内边距 20pt；页面内容使用 `Screen` 统一处理安全区、键盘和滚动。

- 页面区块间距：16–24pt。
- 卡片内部间距：16–20pt。
- 控件之间间距：8–16pt。
- 最小触控目标：44 × 44pt。
- 长页面底部必须为底栏、Home Indicator 和最后一个操作预留空间。
- 宽屏仅增加两侧留白，不改变移动端信息顺序；内容最大宽度由页面 token 控制。

### 3.4 圆角与层级

- 控件：`radius.md`。
- 普通卡片：`radius.lg`。
- 重要 Hero / Sheet：`radius.xl` 或 `radius.sheet`。
- 胶囊只用于筛选、状态和短标签，不用于所有组件。
- 阴影只表达浮层关系，不作为普通卡片的唯一边界；必须同时保留边框或背景层级。

## 4. 页面结构

标准页面顺序：

```text
Screen
  PageHeader / 页面上下文
  当前过滤器（如果适用）
  主要内容
  主要 CTA 或下一步
  辅助说明 / 次要操作
```

页面必须定义以下状态：

- loading：首屏骨架或明确的加载指示。
- empty：说明为什么为空，并提供下一步。
- error：说明发生了什么，并提供重试；不要只展示技术错误。
- success：操作完成后给出即时反馈，并刷新受影响的内容。
- offline / stale：网络不可用时说明数据新鲜度，不伪装成成功。

## 5. 导航与过滤

底栏固定四个一级入口：

```text
Today（当前照护行动）
Timeline（历史记录）
Pet（宠物主体）
More（账号、Family、设置）
```

底栏只承担一级导航，不放“新增”这种业务动作；新增动作放在当前领域页面内。导航必须使用原生 tab 语义、选中态、长按事件和安全区，不能使用 Web fixed CSS 复制。

Pet / Family 过滤器属于展示状态：

- `all`：所有可访问 Pet。
- `family`：该 Family 可见的 Pet。
- `pet`：单个 Pet。

过滤器改变查询参数和页面展示，不创建领域对象，不改变权限，不改变数据归属。

## 6. 组件行为契约

### Button

必须支持 primary、secondary、ghost、danger、loading、disabled、pressed。loading 时禁止重复提交，仍保留可理解的无障碍状态；破坏性操作不能用 primary 伪装。

### TextField

必须有 label、placeholder、error、hint、键盘类型、提交行为和 loading/disabled 状态。错误信息必须靠近字段，并说明如何修复。

### Card

Card 只负责内容分组，不默认意味着可点击。可点击卡片必须使用 `Pressable` 并提供 accessibility label；不可点击内容不能添加 pressed 动效。

### Toggle / Segmented Control

使用原生可访问控件语义，必须有当前值、选中态、禁用态和明确标签。选中不能只由颜色或阴影表达。

### Sheet / Modal

必须处理安全区、键盘、Android 返回键、拖拽关闭、遮罩关闭策略和提交中的不可关闭状态。破坏性确认应优先使用 Sheet，而不是不受控的 Toast。

### Toast

只用于短反馈，不承载关键决策和长错误说明。消息必须可重复查看或有对应页面状态；网络失败、保存失败和权限问题不能只放 Toast。

### Icon

只使用项目图标库。图标需要统一尺寸、描边/填充风格和语义；装饰图标标记为 decorative，操作图标必须有 accessibility label。产品 UI 不使用 Unicode emoji；用户生成内容可以原样保留。

## 7. 交互与动效

- Pressed feedback 立即发生，目标约 80–150ms。
- 页面转场只使用轻微 opacity / translate，不阻塞任务。
- 优先原生 `Pressable` 状态，不模拟 Web hover。
- 所有异步操作必须有 pending、成功、失败三态。
- 同一操作在 pending 期间必须幂等，避免重复请求和重复事件。
- 支持系统减少动效设置；减少动效时保留状态变化和可理解反馈。
- 动效不能承载业务信息，不能让用户等待动画结束才能继续。

## 8. 表单与数据安全

- 表单提交前做本地格式校验，服务端错误必须可映射到具体字段或页面。
- 保存成功后以服务端返回值刷新 UI，不根据本地猜测显示成功。
- 页面离开前保护未保存输入；登录码、邀请信息等敏感数据不得写入普通日志。
- 删除、归档、退出 Family、修改共享权限必须明确影响范围。
- 用户可见的 Pet、Family 和记录内容必须尊重权限查询结果，不能通过 UI 过滤代替后端授权。

## 9. 无障碍与平台规则

- 所有可操作元素至少 44 × 44pt。
- 颜色不是唯一状态信号。
- 支持 VoiceOver / TalkBack 的 role、label、state、hint。
- 支持系统字体缩放，长文本可换行。
- 支持 iOS / Android 安全区、键盘和返回手势。
- BlurView 必须有无毛玻璃时的纯色 fallback。
- 每次组件变更至少检查：键盘、字体放大、深色/低对比环境、空状态、错误状态和窄屏。

## 10. 页面验收清单

每个页面合入前必须回答：

1. 用户进入后是否立即知道当前 Pet / Family / 过滤条件？
2. 主要任务是否只有一个明确 CTA？
3. loading、empty、error、success、offline 是否完整？
4. 是否所有尺寸、颜色和字体都来自 token 或共享组件？
5. 是否存在重复提交、误删、越权展示或静默失败？
6. 是否支持安全区、键盘、返回、字体放大和辅助功能？
7. 是否在真实 iOS / Android 设备上检查 pressed、滚动和底栏遮挡？

## 11. 工程执行规则

- 设计评审以本文件为准，HTML 只作视觉参考。
- 新组件先定义状态契约，再写 UI。
- 页面不得直接导入第三方颜色、图标或阴影。
- 设计 token 变更必须同步更新截图/组件验收。
- 任何无法通过共享组件表达的特殊设计，必须先证明它是产品需要，而不是页面临时写法。
