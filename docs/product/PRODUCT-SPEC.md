## 1. 定位

**宠物一生的智能健康档案与照护协作系统。**

- 一句话：`The AI-powered lifetime health record and companion for your pet.`
- 解决的问题：多人共养同一只宠物时——今天谁做什么、健康信息有没有沉淀、临时交接时给对方多少信息。
- 不是：宠物社交、AI 诊断、医生后台、电商。
- 竞争策略：基础宠物管理（档案/时间线/提醒/分享）是**入场券**，不是差异化；差异化在上层 AI（Import / Search / Vet Summary，见 AI 蓝图）。不打"最好的宠物管理 App"这个红海。

## 2. 最终完全形态（定稿）

### 2.1 实体与数据归属

| 实体 | 归属 | 说明 |
|---|---|---|
| User | 平台 | 账号、身份、权益、（未来）AI 点数 |
| Family（圈） | 成员共同体 | 数据与**责任**边界：成员关系、邀请码、名称/时区设置 |
| Pet | **独立终身数据资产** | 档案、用药、健康事件、任务模板+执行史、分享——全部跟宠物走 |
| Share | 宠物派生 | 最小权限、短生命周期、可撤销的只读交接凭证 |

关键裁定：
- **任务模板属于宠物**（"给 Milo 喂药"是照护配置，不是家庭设置）；家庭删除/宠物转移时随宠物走。仅名称/时区/邀请码是纯家庭资产。
- MEMORIAL（纪念态）宠物仍属于家庭，是家庭历史的一部分。

### 2.2 Family 生命周期

```text
ACTIVE ──移交所有权──▶ ACTIVE（新 owner）        最后 owner 离开只有这两条出路
ACTIVE ──删除请求──▶ 必须清空（无任何宠物，含纪念态）
                 └─▶ SOFT_DELETED（30 天恢复窗）──到期──▶ HARD_DELETED
```

- 最后一个 owner 不可直接退出/被移除（数据库触发器强制）；必须先移交所有权或删除家庭。
- **清空才能删**（AWS 式）：删除家庭前必须逐只处置宠物（转移或显式删除），杜绝误销毁共享记忆。
- 30 天软删除恢复窗防误删；到期硬删。
- **账号注销 ≠ 家庭删除**：注销（确认邮箱）是显式总销毁，名下家庭级联清理；家庭删除才需要"清空"仪式。

### 2.3 Pet 生命周期

```text
ACTIVE ──去世/送养──▶ MEMORIAL（只读、免配额、可导出，停止任务与提醒）──显式确认──▶ HARD_DELETE
ACTIVE ──转移（领养）──▶ 双同意迁移到目标家庭（A 圈 owner 发起 + B 圈 owner 接受）
```

- 转移搬走：宠物全部历史（档案/用药/事件/任务模板+执行史）；自动撤销该宠物全部分享链接；记录 transfer 事件可溯。
- 转移不搬：圈成员、圈设置；记录者引用保留（全局用户表，跨圈名字可解析）。
- 目标家庭按其档位检查宠物槽位。

### 2.4 订阅与配额：**锚定模型（定稿，取代"圈档=圈主权益"）**

> **付费跟人走，人把订阅"锚定"到一个家庭；家庭档位 = 成员中锚定到本圈的最优权益。**

| 规则 | 内容 |
|---|---|
| 权益归属 | 永远在 user 层（谁付钱谁持有；founding = `*` 通配） |
| 锚定 | 持有付费权益的用户有一个锚，指向一个圈；首建圈自动锚定；换锚自助、即时生效 |
| 档位解析 | 圈内成员锚定权益的最大值；无人锚定 = free；不叠加 |
| 降级宽限 | 锚定成员退出/换锚 → 圈降级：存量超额数据**保留可读可导出，仅禁止新增**（永不自动删数据） |
| 防拆圈 | 限制"拥有的家庭"数：free 1 个 / pro 3 个 |
| 锚自动释放 | 锚定成员被移除/退出时，锚解除，圈按规则降级 |
| 个人层配额 | 未来 AI 点数、导出频率等跟 user 走；存储/宠物/成员跟家庭走（数据在那里） |

配额表：

| 限额 | Free | Pro | Founding(`*`) |
|---|---|---|---|
| 拥有的家庭 | 1 | 3 | 同 Pro |
| 成员/家庭 | 2 | 6† | 同 Pro |
| 活跃宠物/家庭（纪念态免占） | 2 | 5（蓝图定价 $4.99 档） | 同 Pro |
| 附件总量/家庭（B6+ 生效） | 50MB‡ | 10GB | 同 Pro |
| 单文件（B6+） | 10MB | 50MB | 同 Pro |

† Pro 成员数蓝图未定，B10 实现锚定时随定价终版复核。
‡ V1.5 客户端现行 50MB；AI 蓝图调整为 500MB（字节计），B6 接附件时以蓝图为准。
另有蓝图 Family 档（$8.99：10 宠/50GB/700cr）在付费版本落地时引入。

**上表数字的运行时事实来源是数据库 `plans` 表**（migration 播种本表数值；
`planet-cli plans set` 修改立即对新写入生效，无需发版）。
新增档位 = plans 插一行 + 发放对应权益 key，零代码变更；降档宽限语义由服务端保证（存量保留、新增拒绝）。

### 2.5 V2+ 扩展（定稿但明确不在 V1）

- `pet_guardians`（宠物守护人）：认领权、转移同意权，与"医疗决定人"对齐——家庭解散时非 owner 成员可抢救宠物档案。
- 孤儿宠物状态（UNASSIGNED + 30 天认领/导出窗）：仅两种来源（家庭删除残余、转移中断）；V1 用"清空才能删 + 30 天家庭恢复窗"覆盖同一安全需求。
- `family_pets` 关联表（一宠多家庭视角）：仅当"宠物同时被多家庭查看"（繁育人/兽医视角）成为真实需求时再做；V1 保持单活跃归属。
- AI 层（Import / Search / Vet Summary）、图片附件（R2）、IAP、推送闭环、数据导出（紧随 V1）。

## 3. 第一版边界（冻结，2026-08-18）

**V1 = 纯数据库形态的完整家庭宠物管理**（无图片/附件，无 AI）。实现进度见 DEV-PROGRESS。

| 能力 | 内容 |
|---|---|
| 账号管理 | 验证码登录即注册（默认 free）、改名、登出、注销（确认邮箱） |
| Family 管理 | 建圈（上限按档）、邀请码加入/滚动刷新、成员列表、移除、退出 |
| 家庭治理 | **所有权移交、删除家庭（清空+30 天恢复）** |
| Pet 管理 | CRUD、MEMORIAL 归档/恢复、硬删（确认）、**转移（双同意）** |
| 健康数据 | 时间线事件（类型注册表）、用药（开始/停自动事件）、档案（过敏/慢病/联系人） |
| 今日协作 | 任务排程（daily/weekly/interval）、幂等完成（409+权威记录）、Undo、7 天补记 |
| 分享 | care_card（零病史）/ summary（段落选择）链接，24/72/168h、撤销即时 410 |
| 套餐限制 | 仅 free 档全量执行（1 家庭/2 成员/2 活跃宠）、usage 端点；限额存 plans 表为未来付费预留 |
| 邀请 | 邀请码机制（含限流防穷举） |

V1 明确**不做**（写死，防范围蔓延）：
**付费/订阅/锚定/多档位/IAP**（锚定模型是 V2 付费落地时的定稿设计，V1 不实现）、
图片附件（R2）、AI、推送、每日摘要、guardians/孤儿态、`GET /usage` 之外的一切运营功能。
数据导出紧随 V1（V1.1 第一件事）。

## 4. 权限矩阵（服务端强制）

| 操作 | Owner | Caregiver | 匿名分享接收方 |
|---|:-:|:-:|:-:|
| 完成任务 / 记录事件 / 上传附件 | ✅ | ✅ | ❌ |
| 编辑宠物档案 / 用药增停 | ✅ | ✅ | ❌ |
| 删除用药 / 任务 / 事件（自己的） | ✅ | ✅ | ❌ |
| 删除事件（他人的） / 删宠 / 归档 | ✅ | ❌ | ❌ |
| 邀请 / 移除成员 / 刷新邀请码 | ✅ | ❌ | ❌ |
| 创建 / 撤销分享 / 转移宠物 / 家庭治理 | ✅ | ❌ | ❌ |
| care_card / summary 只读视图 | — | — | ✅（仅该分享范围） |

非成员访问一律 404（不泄露存在性）；归档宠拒绝写入（409 PET_ARCHIVED）。

## 5. 时间与时区

一切 UTC 存储；"日"粒度（log_date、started_on）按家庭时区（IANA）折算；DST 边界有测试覆盖。
