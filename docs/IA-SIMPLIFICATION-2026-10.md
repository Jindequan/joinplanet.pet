# 页面精简与信息架构方案(IA-SIMPLIFICATION)

> 2026-10-19 founder 令:「页面有点多,嵌套严重,层层都有下一级,页面死循环。
> 必须精简页面,梳理业务:哪些是核心页面,哪些是辅助页面,表单作为子页面存在。」
> 本文=完整方案,**待 founder 批准后施工**。证据口径:37 个路由全量清单+78 条
> 真实跳转边(router.push/replace/href 全形态扫描)+ 入度统计。

---

## 一、业务先于页面:三条主线

页面为业务服务,先立业务再裁页面:

| 主线 | 业务问题 | 承载页 |
|---|---|---|
| **① 今日照护执行** | 今天谁做什么,做完了吗 | Today(tab) |
| **② 记录沉淀** | 宠物的一生发生了什么 | Records(tab) |
| **③ 协作请求** | 请人接手/交接/回应 | Requests(tab) |
| 支撑:宠物档案 | 它是谁、谁管它 | Pets(tab)+宠物详情 |
| 支撑:家庭与订阅 | 圈子与额度 | More(tab)+家庭详情/用量 |

一切页面必须回答:服务哪条主线。答不出的页面就是裁撤候选。

## 二、现状诊断(实锤数字)

- **37 个路由**:5 个 tab + 32 个非 tab(详情 12/表单 9/系统 8/列表 3)。
- **最深链 4 层**:Pets→宠物详情→照护计划→指派管理(`/pets/:id/care/:planId/assignments`),从 tab 起 4 次点击。
- **环感来源(入度实锤)**:家庭类页面吃 19 条入边、宠物类 16 条——每个详情页都是 5-9 个出口的枢纽:
  - 宠物详情 9 出口(照护/编辑/转移/就医摘要/家庭/家庭新建/时间线/升级/激活设置);
  - 家庭详情 8 出口(宠物/宠物详情/新建宠物/新建家庭/转移/时间线/升级/加入);
  - **families↔pets 双向互链**(列表↔列表、详情↔详情)——「死循环」体感的直接来源。
- **同一目标多处入口**:/families 列表 10 个直达入口(宠物详情/账户/设置/请求面板/Today…),多数只是「顺路塞个入口」。

## 三、目标架构:三层封顶

```
L0 核心页(5 个 tab,常驻)
│  Today │ Records │ Requests │ Pets │ More
│
L1 对象页(从 tab 或对象列表进入,描述"一个东西")
│  宠物详情  家庭详情  请求详情  记录详情  交班批次  就医摘要  趋势  用量
│
L2 子页(从对象上下文进入,做一件事就回:全部表单在此)
   新建/编辑宠物  转移宠物  照护计划  指派  新建家庭  加入家庭  家庭转移  通知设置
```

**硬法(防再生,入守卫)**:
1. tab→对象→动作,**三层封顶**——任何第四层路径出现即违规;
2. **详情页出口 ≤4**,且必须属于本对象的动作(宠物详情出口=照护/记录/家庭/更多菜单);
3. **集合页之间零横向跳转**(Pets/Requests/Records/家庭列表互链全删;对象级下钻合法);
4. **表单只住一个父入口**(pets/new 只从宠物上下文进,Today/家庭页的直达改道);
5. 对象间横向查看(宠物↔家庭)用**替换不堆栈**(replace),返回键回到来源而非又一页。

## 四、逐页裁决表(37 → 31)

| 路由 | 裁决 | 理由 |
|---|---|---|
| /(tabs) /timeline /requests /pets /more | **核心保留** | 五 tab,三主线+两支撑 |
| /pets/[id] | **保留·瘦身为对象页** | 出口 9→4(照护/记录/家庭/更多菜单),其余动作收「⋯更多」或去该在的层 |
| /families/[id] | **保留·同瘦身** | 家庭成员/宠物下钻合法;横向入口收 |
| /requests/[id]、/handoffs/[id]、/records/[id] | **保留** | 主线③②的对象页,已合格 |
| /pets/[id]/vet-summary | **保留** | 就医摘要=G1 主功能 |
| /trends、/account/usage | **保留** | 数据/用量,More 入口 |
| /paywall | **保留** | 升级动线(5 入口合法:撞墙/More/账户/趋势/宠物) |
| /auth、/invite/[code]、/share/[token]、/s/[token] | **保留** | 系统:登录/邀请/匿名分享 |
| /pets/[id]/care + assignments | **合并** | 指派管理降为 care 页内的管理 sheet——**消灭唯一的 4 层链** |
| /families(列表) | **退役合并** | 家庭列表的家=scope 弹层(全局已有)+家庭详情;10 个直达入口改道(→具体家庭详情或返回);More「家庭」入口改「家庭管理 sheet」 |
| /families/new、/families/join | **保留为子页** | 表单;入口唯一化(从家庭上下文/scope 层进) |
| /families/[id]/transfers、/pets/[id]/transfer | **保留为子页** | 表单;入口=各自详情页 |
| /pets/new、/pets/[id]/edit | **保留为子页** | 表单;**删 Today 直达入口**(第 4 法) |
| /settings + /settings/notifications | **并入 More** | 设置两页降为 More 区块+notifications 改 sheet——More 本就是「更多设置」的家 |
| /account + /account/deleted | **合并** | deleted 降为 account 内空态分支 |
| /activation + /activation/setup-care | **合一** | 激活向导单页分段(setup-care 为段二),少一层路由 |
| /ui-lab | **dev-only** | 生产构建禁入(条件路由) |

**账单:37 → 31 条路由(生产可见 30),最深链 4 层 → 3 层,家庭类入边 19 → ≤6,宠物详情出口 9 → 4。**

## 五、施工顺序(批准后)

1. **批一(去环,纯导航改道,零 UI 重做)**:详情页出口收敛+replace 语义+/families 十入口改道+集合页互链删除——体感立变,风险最低;
2. **批二(降层)**:assignments→care 内 sheet;settings→More;deleted→account;activation 合一;ui-lab dev 门;
3. **批三(退役)**:/families 列表路由退役+More「家庭管理」sheet 承接;
4. 每批过全部门禁(e2e 按新动线改写断言)+守卫加五条硬法+PAGE-MAP/RULINGS 同步。

## 六、不做什么

- 不动五 tab 结构与底栏(既有裁决);
- 不砍任何业务能力——只动「入口与层级」,功能全部保留;
- 不做推测性重设计——本方案每一刀对应上文实锤数字。
