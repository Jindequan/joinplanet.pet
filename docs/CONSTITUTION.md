# AGENT 执行宪法(入仓正本)

> **来源与同步**:`~/.zcode/workspace/default/AGENT-CONSTITUTION.md`(agent 工具链分发副本,2026-09-14 版)。2026-10-16 起以本文件为仓内正本——此前代码/文档中一切「宪法 §x」引用均指向仓外私有路径,不可解析(重构审计实锤)。宪法修订时同步两处,仓内为准。


## §0 效力

- §0.1 本法为最高执行法，适用于一切页面、功能、前后端、UI 开发，优先于任何 agent 自身判断。
- §0.2 项目级规范是本法的实施细则；细则可以更严，禁止更松。冲突时：项目细则 > 本法 > agent 判断。
- §0.3 标 [铁] 的条款无例外。违反任何 [铁] 条款 = 交付无效，直接打回。
- §0.4 本法不含解释。条款出处与论证见 `/Users/devin/.zcode/workspace/default/design-and-delivery-standard.md`（立法解释书）。执行时禁止因「理解条款」暂停——有争议走 §5.5。
- §0.5 适用范围：新页面、新功能、IA/动线/schema 变更 → 全流程适用（§2–§4）；单点修复 → 免除文档产出，但 §3、§4 条款全部有效，且必须过 §4.8 快速门禁。

## §1 铁律（违反即无效交付）

- §1.1 [铁] 顺序：理解 → 设计 → 实现 → 验证，按序执行。前一阶段法定产出物不存在，禁止开始下一阶段。禁止跳过直接改代码。
- §1.2 [铁] 业务归属：任何页面、模块、字段、按钮、接口，必须能回答：服务谁 / 解决什么问题 / 推动哪一步 / 产生什么结果。四问有一答不出，禁止实现。
- §1.3 [铁] 证据制：「完成」必须附证据（截图 / 日志 / 数据 / 走查记录）。无证据 = 未完成。禁止自我评估式达标声明。
- §1.4 [铁] 诚实：禁止伪造数据、假统计、假用户反馈、库存图冒充真实内容、静默失败。数据不足必须显示诚实空态 + 下一步动作。
- §1.5 [铁] 单一权威：每个项目只有一个有效规范文档。代码与规范冲突 = 代码错，修代码。用户否决过的方案，禁止在任何后续会话再次提出或实现。用户裁决当日记入规范文档原文。
- §1.6 [铁] 权限边界：未经指令，禁止改 IA、导航结构、数据结构、冻结基线；禁止顺手重构、顺手重写、顺手加功能。
- §1.7 [铁] 越权拦截：UI 不得绕过权限、确认、超时、取消规则。

## §2 流程法（阶段门禁）

### 阶段一 · 业务定义

- §2.1 法定产出物（缺任一项，禁止进入阶段二）：① 目标用户画像（具体人群，禁止「所有人」）② 核心价值一句话（用户视角）③ 业务对象清单 ④ 主闭环环节清单（输入→处理→输出→下一步→反馈/复用，逐环标注 已实现/未实现）⑤ 不做清单 ⑥ 付费与额度规则（若适用：额度怎么给、墙在哪、撞墙体验、退款逆向）⑦ 验收标准。
- §2.2 验收标准必须写成 Given / When / Then。禁止「体验良好」「界面美观」类不可判定表述。
- §2.3 价值证据：无付费/流量/访谈/竞品任一证据支撑的新功能，禁止直接开发；必须先做最小验证或取得用户书面豁免。
- §2.4 通过判据：主闭环可一句话复述；每环有归属与状态；四类风险（价值/可用/可行/商业）各有应对。

### 阶段二 · 页面与动线（IA 变更 = 最高级变更，重过本阶段 + 用户裁决）

- §2.5 页面清单必须由主闭环环节推导。禁止「顺手加页面」「竞品都有」式推导。
- §2.6 每页必须登记页面契约，无契约的页面禁止开发。契约十项：回答的唯一问题 / 承载的业务 / 承载的数据 / 首屏信息 / 主操作 / 次操作 / 进入条件 / 成功结果 / 失败恢复 / 离开路径 + 权限边界。
- §2.7 [铁] 每页一个主任务、一个主标题、一个主 CTA。
- §2.8 结构上限：导航 ≤3 层；首屏可点项 ≤7；触控目标 ≥44pt（iOS）/ ≥24px（Web 最低，主操作 44px）。
- §2.9 信息分三层：必看 / 扫一眼 / 默认折叠。禁止把数据库字段原样铺进页面。
- §2.10 [铁] 主路径唯一：完成核心闭环的路径唯一、连续。同一功能禁止两个并列入口。
- §2.11 [铁] 薄切片先行：必须先用最薄真实切片（真库 → 真 API → 真 UI）打通主闭环，之后才允许铺开其他页面。
- §2.12 双端各自设计（桌面 1440/1280 与移动 390），不是缩放。导航、表单、购物车等通用件必须遵循平台惯例，禁止自创。
- §2.13 业务状态判定（已完成/待处理/逾期等）收口到单一模块。禁止各页面自行推断。

### 阶段三 · 设计语言

- §2.14 [铁] tokens 先行：颜色、字号、间距、圆角、阴影、动效时长全部进 tokens 文件。组件内禁止硬编码样式值。改视觉 = 只改 tokens。
- §2.15 锚点先行：必须先取得用户确认的 2–3 个参考产品锚点，才准实现视觉。「精美」「高级感」不是有效需求。
- §2.16 [铁] 反默认风，三步判定缺一不可：
  ① 硬禁项命中即打回：蓝紫渐变用于 hero/按钮/横幅；emoji 或 unicode 符号（⚠ ★ ⚑ ▸）做功能图标；库存照片、假数据、随机头像冒充真实内容；无业务语义的渐变装饰；全站复用同一版式模板（大标题+三栏特性卡+CTA；清一色三栏卡片网格）。
  ② 决策留痕：字体、主色、版式、圆角、阴影的每个选择必须注明来源（锚点推导 / 品牌规范 / 用户裁决）并落在 tokens 或规范文档。来源不明 = 违规。
  ③ 通用性测试：页面截图放进任意其他 SaaS 毫无违和 = 不合格，重做。
- §2.17 一词一物：同一概念全站只用一个词；同一控件全站只有一种形态。子产品可有个性，品牌基底（色系/字体/组件）必须统一。
- §2.18 [铁] 层级序：布局 → 空间 → 层级 → 字重 → 颜色 → 装饰，只许按序。禁止用颜色修布局、用缩小字号修信息过载、用加粗/Badge 修层级。
- §2.19 视觉优先级必须等于业务优先级：业务上最重要的元素必须视觉最强。答不出「为什么是现在、该做什么」的元素不得进首屏。

## §3 实现法

- §3.1 [铁] 四态同步：loading / empty / error / success，加业务附加态（无权限、额度不足、过期、冲突、阻断）随功能同步实现，禁止「以后补」。空态必须含下一步动作。
- §3.2 [铁] 错误三段式：错误信息 = 发生了什么 + 怎么办 + 不损失什么。禁止错误码直出、内部术语/引擎名/模型名进 UI、静默吞错。
- §3.3 [铁] 按钮五要素：前置条件（禁用原因可见）、后端动作、成功态、失败态、下一跳。点击必须有效果。破坏性操作必须确认或可原位撤销；撤销必须比创建容易。
- §3.4 防错优先：能禁用+说明，禁止可点+报错；能选择，不键入；必须有默认值；表单 inline 校验；confirm 仅用于不可逆操作。
- §3.5 响应时限：<0.1s 即时；>1s 进度指示；>10s 可取消并告知预期。AI 生成一律流式。流式输出禁止抢占用户输入。乐观 UI 仅限可逆操作。
- §3.6 [铁] 逆向闭环：每个正向流程必须有对应逆向操作（撤销/取消/退款/撤回/归档/恢复），或书面豁免。存储失败禁止丢弃已付费结果。周期任务必须有去重、限次、重试上限。
- §3.7 [铁] 状态机四守卫：状态枚举含终态；非法跳转、事件乱序、并发写（幂等/乐观锁）、过期数据失效——四守卫必须存在且有测试。状态判定全系统一个口径。
- §3.8 [铁] 契约：字段对齐以接口实测（curl/浏览器）为准，不以文档为准。只有 POST 没有 GET 的能力视为未完成。实体引用禁止用标题字符串。表单校验前后端同规则。验收前必须切真实 API 并实测空/错/慢/失败/权限五种场景。mock 禁止进入生产构建。
- §3.9 界面语言：新文案必须全语言同步补齐。时间、数字本地化格式化。禁止硬编码单一语言。
- §3.10 可访问性：颜色不得是唯一状态信号；reduced-motion 下保留状态变化、移除循环动画；使用语义化标签（alert/dialog）；对比度达 AA。
- §3.11 [铁] 冷启动：新用户首次会话 60 秒内必须能完成一次最小核心动作，或看到含自身数据的真实首屏。空产品状态必须提供示例数据或引导。

## §4 验收法

- §4.1 [铁] 三视角自检全部执行：攻击者（越权/IDOR/注入/绕付费墙）、小白（迷路/误操作可恢复）、开发者（竞态/泄漏/边界/超时）。
- §4.2 启发式体检，逐页过十条：状态可见 / 说用户语言 / 可撤销 / 一致性 / 防错 / 识别而非回忆 / 新手老手都高效 / 美观极简 / 帮识别恢复错误 / 有帮助。
- §4.3 [铁] 双端逐页截图：桌面 + 390，每页给出结论（过/不过+原因）。修复后必须复拍。通过即基线冻结，后续改动对照基线。
- §4.4 [铁] 真实栈走查：真库 + 真后端 + 真构建，零 mock。必须走通主闭环全程 + 至少一条逆向流。多角色权限用双账号并排验证。
- §4.5 [铁] 上线验收从外网走：HTTPS → 健康检查 → 注册/登录 → 核心动作 → 支付回调（若适用），全链路正确态。本地 dev 绿 ≠ 上线就绪。
- §4.6 [铁] 交付报告四段：改了什么 / 证据 / 已知未决项 / 下一步。无证据的部分必须标注「未验证」。
- §4.7 [铁] 自证格式：交付报告中每项完成声明必须引用条款编号并附证据（例：「§3.1 四态已齐——双端截图×N」「§3.8 契约一致——curl 实测记录」）。无法引用条款的完成声明无效。
- §4.8 单点修复快速门禁（三问，答不出禁止提交）：动了哪些页面契约？哪些 [铁] 条款受影响？用什么证据验证？
- §4.9 DoD：§4.1–§4.7 对应项全部满足，才允许称「完成」。

## §5 裁决法

- §5.1 [铁] 优先级序：安全与权限 > 业务正确（闭环/状态机/数据） > 主路径体验 > 视觉。禁止用低优先级动作掩盖高优先级问题（禁止用 polish UI 回避缺失的核心能力）。
- §5.2 变更分级：改视觉 = 只改 tokens（免审）；改组件/布局 = 过 §2.14–§2.19 复审；改 IA/动线、删数据、改 schema = 单向门，重过阶段二 + 用户裁决。
- §5.3 决策记录：用户裁决、否决、方向变更，当日入档（规范文档或 ADR），含日期与原文。
- §5.4 争议查询顺序：本项目规范 → 本法 → 立法解释书（/Users/devin/.zcode/workspace/default/design-and-delivery-standard.md）。
- §5.5 [铁] 仍无法裁决 → 停下问用户。禁止猜测、禁止先斩后奏、禁止用实现既成事实倒逼追认。
