# 订阅版设计(PRO / PLANET 2.0)2026-10-13 r2

> 触发:founder 2026-10-13 指令「更完善的版本+订阅计划」,同日追加「**至少三档、差异化、定价策略、各方面容量上调**」——本文取代「MVP 不做付费」旧裁决(2026-09-22);SAAS-PREP「付费基建不双建」的 C 端前置就此满足。
> 硬约束先说死:**iOS App 内卖数字权益必须走 Apple IAP**(审核指南 3.1.1),landing 的 Lemon Squeezy 通道不可用于 App 内 Pro;Apple 抽成 15%(小企业计划)。

## 0. 结论先行

1. **铁律:免费档保住协作闭环的完整**——Today/请求/交班/通知/时间线/分享全部免费。北极星 WAP 靠第二照顾者进来,任何把协作放进付费墙的设计都是自杀。付费档卖「广度与深度」,不卖「协作本身」。
2. **四档体系:Free + Plus + Pro + Unlimited**(founder 要求三档付费,Free 保持不动——第 3 只宠物是最强付费钩子,动免费档就拆钩子)。
3. **每档一句话身份**:Free「两人两宠完整协作」/ Plus「小家庭的照片自由」/ Pro「多宠家庭主力档」/ Unlimited「照护中枢/繁育者顶配」。差异化维度:宠物数、席位、存储、AI、家庭共享、优先支持。
4. **定价:Plus $2.99/月·$19.99/年;Pro $5.99/月·$39.99/年;Unlimited $11.99/月·$99.99/年**——三档阶梯用锚定心理学把主力档推成默认选择(§3)。
5. **技术路径 = StoreKit 2 + App Store Server API 验签 + notifications v2 webhook 写 subscriptions 表**;判定链(subscriptions→BestKey→配额)是生产代码,需扩:三档排序、plans 三行数值迁移(0038)、paywall 三档对比页、**Apple 家庭共享**(一个订阅全家用,与锚定方案 A 天然自洽)。
6. 版本编排:**1.1(可观测,已在途)先发;2.0 = 订阅 + 完善功能包**(§6),工程量约 4 周。
7. **最长前置是 ASC 付费应用协议+银行税务(只有 founder 能办),建议今天就启动**——它不阻塞开发,但阻塞上线。

## 1. 铁律:北极星保护(不可谈判的设计底线)

免费档必须永远完整拥有:F4 今日照护协作、Care Request 责任链、批量交班、通知、时间线记录、就诊摘要快照、分享、导出、2 只宠物、2 人家庭。

理由:漏斗里「8 invite another caregiver」是北极星前置环节——**第二照顾者绝不能撞付费墙**(他免费进来、免费协作,才有多宠多记录的深化需求)。Pro 的每一个卖点都必须是「用得深了才撞到的墙」:第 3 只宠物是「爱」的证明(C12 需求簇实证:五豚鼠家庭/四犬三只特殊需求),照片多了才需要 10GB,家人多了才需要 5 席。

## 2. 档位与权益(四档差异化)

| 权益 | **Free**<br>两人两宠·完整协作 | **Plus**<br>小家庭·照片自由起步 | **Pro**<br>多宠家庭主力 | **Unlimited**<br>照护中枢/繁育者 |
|---|---|---|---|---|
| 协作闭环全部功能 | ✅ | ✅ | ✅ | ✅ |
| 活跃宠物 | 2 | **4** | **8** | **30**(工程上限,语义=「实际不设限」) |
| 家庭成员席位 | 2 | **4** | **8** | **15** |
| owned families | 1 | 1 | 2 | 3 |
| 照片存储 | 50MB | **5GB**(百倍) | **25GB** | **100GB** |
| 单文件上限 | 10MB | 25MB | 50MB | 100MB |
| AI 月配额(Pet Intelligence,V3 上线生效) | 0 | 0 | **20** | **100** |
| Apple 家庭共享(一份订阅全家 Apple 设备用) | — | — | ✅ | ✅ |
| 优先支持(support@ 优先处理) | — | — | — | ✅ |
| 定价(月) | $0 | **$2.99** | **$5.99** | **$11.99** |
| 定价(年) | $0 | **$19.99**(≈$1.67/月) | **$39.99**(≈$3.33/月) | **$99.99**(≈$8.33/月) |

设计说明:

- **Free 一字不动**(0032 冻结):第 3 只宠物是最强付费钩子(C12 需求簇:五豚鼠家庭/四犬三特殊需求),免费档放宽等于亲手拆钩子;且「免费完整协作」是官网信任叙事的地基。
- **宠物数阶梯 2/4/8/30**:2→4 覆盖「再养一只」;8 覆盖真实多宠家庭+轻度寄养;30 是工程语义的「不设限」(配额执法按数字比对,真无限要改语义,没必要)。
- **席位阶梯 2/4/8/15**:2 人免费保协作;4 人=核心小家庭+保姆;8 人=重组家庭/合租共养;15 人=繁育者小团队/寄养网络雏形(与 SAAS-PREP org 试点自然衔接:个人 Unlimited 先接住,组织化再转 org_pilot 人工档)。
- **存储 50MB→5GB→25GB→100GB**:50MB≈几百张压缩照片(免费够记文字+少量图);5GB 起是「拍照自由」;100GB 面向照片重度+视频未来。
- **AI 只给 Pro 以上**:Pet Intelligence 是 V3 旗舰权益,plans 表 `ai_monthly` 计量键已预留;档位表先定归属,功能上线时才公布(避免宣传未上线功能触审核红线)。
- **家庭共享给 Pro+**:Apple 订阅开 Family Sharing 零抽成、零工程(Apple 侧配置),却是「家庭照护 App」最贴脸的感知价值;Plus 不开是刻意的升级阶梯。
- 超额宽免原则不变:降档/掉订只挡新增写入,存量读/编辑/删除/导出永不受影响(已上线语义)。
- 组织/救援站继续走 org_pilot 人工档(SAAS-PREP 红线:组织档无自助注册),不进此购买面。

**plans 表落地**:新增 plus/unlimited 两行,pro 行数值上调(6→8 宠、5→8 席、10→25GB、3→2 家),Free 行零改动——迁移 0038 一次性收口;BestKey 排序补 `unlimited(95)>pro(80)>plus(65)`(现排序 `*>founder(90)>premium>pro(70)>其他60`,premium 历史预留位让给 unlimited 之下即可,founding seat 映射 Unlimited 等价)。

## 3. 定价策略

**阶梯与心理(三档定价法,主力档=Pro 推成默认)**:

1. **Plus $2.99/月 = 入口锚**:贴 PokiPaw($2.99)同价位但权益更宽(4 宠 vs 其窄面)——「最便宜的认真选择」;
2. **Pro $5.99/月 = 主力与默认**:对比锚——Pro 年付月均 $3.33,只比 Plus 月付贵 $0.34,**把 Plus 的比价对象从 Plus 月付引导到 Pro 年付**(经典 decoy:Plus 月 $2.99 vs Pro 年 $39.99 并排展示,年付 Pro 显得近乎白送差额);权益断崖(8 宠/25GB/AI/家庭共享)让多宠用户无脑选;
3. **Unlimited $11.99/月 = 顶配锚+利润位**:拉高价格上限让 Pro 显得克制;真实吸纳繁育者/重度用户(Breedera £9.99 验证该人群付费力);15 席+优先支持给「小规模组织化」一个自助出口,同时为 org_pilot 人工档留出身份校验理由。

**周期策略**:月/年双周期,年付一律 ≈6.7 折(行业惯例);**年付 7 天免费试用**(Apple 原生支持)——试用门槛只给年付,把高留存意图用户导向年付。

**外部锚对照**:PokiPaw $2.99/月(权益窄)/ DogLog 按宠物包一次性收费 / Breedera £9.99/月(专业繁育)——我们三档恰好把这条价格带从下沿到上沿全覆盖,且每一档都能说出「比 ___ 便宜/值」的一句话。

**升降级与退款**:档位升降级由 Apple 按剩余价值自动折算(同订阅组);退款走 Apple 客服,EXPIRED/REFUND 通知映射已有设计(§5);founding seat(landing,Lemon Squeezy)= Unlimited 等价永久,经 entitlements 手动发放(通道已有)。

**定价的验证回路**:E5 撞墙计数已上线(批 1 funnel)——上线两周看「2/2 撞墙账户数」与 Plus/Pro 转化比,数字不对就调(数字住 plans 表+ASC 价格,热调成本低)。

## 4. 锚定模型(历史未决,founder 2026-08 击穿 D2 的点)

**方案 A(推荐):个人订阅,权益作用于「其 owned 家庭」。**
- 谁付费谁受益:订阅者的 BestKey=pro,他 own 的家庭配额升 pro(pets/members 按 owner 判定——**现行代码就是这么执法的**,families/service.go:404-420);
- 宠物转移:配额跟随目标家庭 owner 的档位——转移给免费亲戚,那边的家庭按 free 判定(存量宽免,不删宠);
- 订阅者换家庭/新建家庭:他的订阅随身(个人属性);
- 后端**零语义变更**,只有「IAP→subscriptions 行」一段新代码。

**方案 B(不推荐):宠物/家庭锚定**——付费权益挂在宠物上,去世/转移的退坡规则复杂,要改配额执法的归属维度,工程量与出错面大。

A 的已知取舍(如实):家庭里付费者退出/被移除后,家庭降回 free(宽免生效)——这正是「个人订阅」的诚实语义,文案要写清。

## 5. 技术路径(IAP 全链)

```text
[APP] StoreKit 2 订阅页(档位/恢复购买/管理订阅深链)
   └─ 购买/续订 → JWS 交易
[server] POST /api/v1/billing/verify(JWS 验签:App Store Server API v2,
   Apple 根证书链本地验证,不依赖共享密钥)→ 写 subscriptions 表
[Apple→server] App Store Server Notifications v2(DID_RENEW/EXPIRED/REFUND/
   GRACE_PERIOD)→ 同步 subscriptions 状态(公网端点+握手验证)
[判定链] subscriptions → BestKey → 配额执法(全部现有代码,零改动)
```

要点:
- **订阅组「PLANET」含 6 个 SKU**:Plus/Pro/Unlimited × 月/年(同组内升降级 Apple 自动折算);
- **BestKey 排序扩档**:`unlimited(95) > pro(80) > plus(65)`,founding seat 映射 Unlimited 等价;
- subscriptions 表(0001)字段已兼容(status/plan/expires_at/deleted_at),三档 plan 键直写;
- **家庭共享**(Pro+):Apple 侧订阅组勾选 Family Sharing 即可,服务端无需感知(Apple ID 维度在设备侧生效,与锚定方案 A「付费者家庭受益」语义自洽);
- **Restore(恢复购买)必须有**(苹果审核硬要求),走同一 verify 端点;
- 沙盒+TestFlight 全链验证后再提审;
- 掉订宽限(GRACE_PERIOD)按 Apple 通知映射,不自己发明;
- App Store Server Notifications 的 S2N 端点挂 api.joinplanet.pet 公网路径(照 S2N Apple 登录回调的既有模式)。
