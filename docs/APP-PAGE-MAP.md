# PLANET 页面地图与交互契约

状态：2026-09-14
用途：作为 APP 页面、路由入口和交互层级的施工基线。它不新增业务对象；所有页面都围绕 User → Family → Pet → Care Occurrence / Pet Event 展示和操作。

## 0. 当前视觉方向：家庭操作台

PLANET 的页面不是“宠物内容墙”，也不是通用任务管理后台。视觉中心是一个家庭成员打开后能立刻执行的照护工作台：当前要做的事使用深绿承载，待处理使用珊瑚色提醒，历史和管理内容退到浅色背景与平面列表。

- 基础色：石灰背景 `#E9E8E1`、纸面 `#FFFDF9`、正文墨色 `#252B26`、工作台深绿 `#1D5A43`、协作珊瑚 `#CB654E`、辅助薄荷 `#D5ECDF`。
- 版式：桌面端左侧固定 220px 工作区导航，内容区最大 1120px；移动端保留同样的五个入口，使用底部导航。主内容左对齐，不用居中营销式首屏。
- 层级：一个页面只保留一个主标题和一个主动作；状态摘要只回答“现在要处理什么”，不再重复一份任务列表。详情页用分区和标签切换，不把每个分区再拆成独立入口。
- 组件：减少统一圆角卡片和阴影的使用；卡片只承载状态边界，普通事实使用分隔线列表。深绿只用于当前入口、执行状态和主动作，不能作为装饰背景到处铺开。
- 文案：只描述人、宠物、事项、时间和下一步动作；不使用无法点击或无法验证的抽象口号。

## 1. 先定结论

- 当前 `APP/app` 有 **37 个路由文件**。它们不是 37 个一级入口，而是 5 个主入口、3 个对象工作区和一组二级管理/弹层页面；其中 2 个是布局文件、4 个是兼容/分流重定向。
- 底栏固定 5 项：**今天、请求、宠物、记录、更多**。今天是执行第一入口；请求是协作的第一入口，出现待回应时显示数量角标；家庭治理和低频设置仍放在更多。
- 页面最多 3 层：`主入口 → 对象工作区 → 单一动作页`。表单、确认、范围选择和响应选择器用 sheet/dialog，不再继续推深路由。
- 所有带范围的页面顶部都必须能看见当前范围：`全部 / 家庭 / 宠物`。范围是查询过滤，不是新的业务对象。
- 范围选择器遵循单向收窄：单击家庭立即切换到家庭并保持选择器打开，继续单击宠物才收窄到宠物；单击“全部”或宠物后关闭。
- 一个页面只能有一个主标题、一个主 CTA；其它操作根据风险分成次操作和危险操作。

## 3. 页面清单

### 3.1 主入口（5 个）

| 路由 | 页面回答的问题 | 首屏信息 | 主操作 | 次操作 / 入口 |
|---|---|---|---|---|
| `/` | 此刻要为宠物做什么？ | 日期、范围、多宠物今日概览、待回应、完成进度、下一项、责任人 | 完成本次照护 | 跳过、撤销、我来做、我也不行、给其他人、调整这一次、记一笔；多成员卡默认突出“我来做”，其它安排方式收进“更多”；临时记录和家庭摘要默认收进“更多照护工具”，需要时再展开；多家庭记录先选可写入的家庭 |
| `/(tabs)/requests` | 哪些照护请求需要我处理？ | 待我回应、我发出的、当前责任链状态 | 打开请求并回应 | 打开原事项 |
| `/(tabs)/timeline` | 最近发生了什么？ | 当前范围、按日期分组的事实流、记录人 | 记一笔 | 编辑、删除、加载更早记录 |
| `/(tabs)/pets` | 有哪些宠物，哪只需要注意？ | 活跃/归档数量、今天待做、宠物卡片 | 添加宠物 | 打开宠物、恢复删除档案 |
| `/(tabs)/more` | 我们是谁，怎么一起照护？ | 当前账户、家庭数 | 打开家庭管理 | 趋势、设置、账户名、设备安全、退出 |

主入口共同规则：先显示范围，再显示页面主叙事；请求角标只表示待回应数量，不在底栏展开第二套状态。桌面端把同样的 5 项放进侧栏，不增加平行业务入口。

All 范围的 Today 在日期之后先显示一张“今天的家庭状态”总览：汇总所有家庭的待处理、已完成和预警，并以一行一个家庭的方式直达家庭 Today；不重复渲染多张完整摘要卡。家庭或宠物范围则直接进入对应范围的执行清单。

Today 的责任条是多成员家庭的统一协作入口：每条未完成 Occurrence 都显示当前负责人或“还没人负责”，并按状态提供“我来做 / 我也不行 / 给其他人”。已经有人确认负责时，其他成员只能查看安排；请求中心只处理待回应和责任链，不复制待办。

Today 的风险卡只投影当前选定家庭时区中的日期；历史日期的逾期风险仍由调度器保留并处理，不混入今天的事项列表。

所有页面读取照护状态时统一经过 `APP/src/core/presentation/care-status.ts`：服务端日志和 Occurrence 状态都可作为事实来源；`已完成`、`已跳过`、`已处理`、`待处理`不能由页面自行用 `!log` 猜测。

### 3.2 Pet 工作区（1 个对象页 + 3 个固定分区）

| 路由 | 页面回答的问题 | 信息分区 | 可操作功能 | 权限边界 |
|---|---|---|---|---|
| `/pets/[petId]` | 这只宠物现在是什么状态？ | 头像/身份、今日待做、档案、健康资料、家庭关联、各家庭成员及“可参与/只查看”状态、分享 | 宠物所有者管理家庭关联、打开家庭成员管理、外部分享和导出；宠物所有者或关联家庭 owner 可归档/删除；宠物所有者或源家庭 owner 可发起转移，目标家庭 owner 接受后才变更所有权；转移会移出源家庭并迁移照护计划，历史事实仍随宠物保留；所有者或档案编辑者编辑健康档案；可参与成员记体重、写时间线 | viewer 只读；照护成员不显示宠物治理入口；删除后的恢复仅由宠物所有者在保护期内执行；归档后只保留历史和导出；多家庭未选定范围时暂停依赖家庭的写入 |
| `/pets/[petId]/care` | 当前家庭以后按什么规则照护？ | 当前家庭、活跃计划、循环规则、下次时间、负责人、用药 | 当前家庭 owner 或宠物所有者可创建、编辑、暂停/恢复、删除计划并管理负责人；家庭成员执行具体事项；添加/停止用药仍按宠物档案写权限 | caregiver 可执行被安排的事项；viewer 只读 |
| `/pets/[petId]/timeline` | 这只宠物完整经历过什么？ | 宠物范围事实流、日期分组、记录人、家庭上下文 | 记一笔、编辑、删除、分页 | 沿用当前家庭—宠物权限；多家庭新记录只列出当前用户可写入的家庭 |
| `/pets/[petId]/care/[planId]/assignments` | 这条计划由谁按顺序负责？ | 主负责人、备用负责人、当前顺序、成员角色 | 家庭 owner 或宠物所有者设为主负责人、设为备用、移除负责人；其他成员查看顺序 | 家庭 owner 或宠物所有者可写；其他成员只读 |

Pet 工作区的分区是同一页面内的 tab，不再把档案、照护、记录做成互相孤立的产品。进入单项管理页后最多再下一层。

### 3.3 Family 治理（6 个）

| 路由 | 功能 | 首屏必须清楚 | 主操作 |
|---|---|---|---|
| `/families` | 家庭列表 | 当前用户属于哪些家庭、角色、时区、今天待处理数量 | 新建家庭 / 打开家庭 |
| `/families/new` | 创建家庭 | 创建后自己成为 owner | 创建家庭 |
| `/invite/[code]` | 公开邀请预览 | 邀请人、宠物、加入权限和邀请码状态；未登录先登录并回到加入页 | 登录后加入 / 加入家庭 |
| `/families/join` | 加入家庭 | 邀请码是否有效、将看到什么、加入后能做什么 | 加入家庭 |
| `/families/[familyId]` | 家庭照护与治理工作台 | 深绿家庭工作区先显示家庭、当前角色、成员/宠物数量、今天待处理/已完成；下方再看下一项照护、成员、共享宠物、最近治理变更和删除条件 | owner 在工作区直接邀请成员 / 添加宠物；所有角色可打开同一家庭范围的 Today；查看成员、家庭和宠物转移操作记录 |

家庭详情的操作顺序固定为：今日照护概况 → 成员与权限 → 宠物与共享 → 邀请/转移 → 家庭设置 → 危险区。删除家庭只有在没有其他成员、没有共享宠物时可用；页面要直接解释阻塞原因。

### 3.4 照护协作（5 个）

| 路由 | 功能 | 关键状态 | 操作 |
|---|---|---|---|
| `/(tabs)/requests` | 照护请求中心 | 深绿协作指挥板先显示待回应、我发出、批量安排；下面才是当前状态和责任链 | 打开请求 / 打开原事项 |
| `/requests/[requestId]` | 单项责任链 | 谁发起、哪只宠物、哪一项、当前等待谁、历史 | 我来做 / 我也不行 / 给其他人 |
| `/handoffs/[batchId]` | 整段交班 | 覆盖哪些 Occurrence、成员覆盖度、逐项结果 | 接手 / 拒绝 / 继续安排 |
| Today 内责任卡 | 当前事项责任投影 | 负责人、等待对象、同步状态 | 回到请求详情 |
| 通知动作回流 | 系统通知深链 | 不能完成/重复交班时说明原因 | 回到同一责任卡 |

当前 Web / 原生工作区还必须保留一张全局来人请求卡：当成员收到新的照护请求时，
无论正在 Today、记录、宠物还是更多页面，都能直接看到“谁请你处理哪只宠物的哪件事”，
并在卡片上选择“我来做”、进入“我也不行”继续找人，或打开完整请求详情。卡片只是当前请求
的入口，不复制一份待办；接受后仍由原 Occurrence 和请求状态负责刷新所有页面。

照护请求永远附着在原 Occurrence 上，不能在请求页面创建第二条待办。`sent/seen` 时原事项不能再次完成或重复转交；完成、拒绝、过期、离线同步都必须显示真实当前状态。

## 4. 入口与层级规则

### 4.1 页面深度

```text
主入口（0）
  → 对象工作区（1）
    → 单一动作页（2）
      → sheet / dialog（不算路由层）
```

禁止：从 Today 跳到家庭设置再跳到宠物转移；应通过当前对象的直接入口或关闭当前 sheet 返回。任何超过 3 层的新增路径必须先说明为什么不能用 sheet 或对象工作区。

### 4.2 CTA 层级

1. 主动作：当前页面最重要、最宽、最容易找到的按钮。
2. 次动作：同一对象的可逆操作，例如跳过、调整、编辑。
3. 治理动作：成员、共享、转移，放入明确分区。
4. 危险动作：归档、删除、撤销权限，放在页面底部并确认；删除必须可恢复或明确保护期。

### 4.3 统一状态词

| 状态 | 用户看到的事实 | 允许的下一步 |
|---|---|---|
| 待处理 | 还没有执行记录 | 完成 / 跳过 / 参与 / 给其他人 |
| 等待回应 | 已发给指定成员，正在等回答 | 查看责任链；不能重复完成/转交 |
| 已确认负责 | 某人已答应 | 该负责人完成；其他人只看 |
| 正在同步 | 本机已保存，服务端尚未确认 | 等待或重试；不能重复提交 |
| 已完成 / 已跳过 | 已写入事实流 | 撤销；撤销后回到待处理 |
| 已逾期 / 无人负责 | 到期但没有有效负责人 | 参与或继续安排；不能伪装成完成 |
| 只查看 | 当前家庭角色无写权限 | 查看全部记录；写操作隐藏或禁用并解释原因 |
