PLANET Design System

宠物护理协作平台 — 设计规范与前端开发标准

版本 1.0.0 2026-08-21 面向开发仓库

01. 设计原则

核心定位

PLANET 不是社交应用，不是医疗诊断工具，不是待办清单。它是一个围绕「宠物生命」展开的协作系统。所有设计决策必须服务于以下闭环：

Pet → Care → Action → Event → Memory

五大设计原则

1. 温暖而不幼稚

宠物是家人，不是玩具。界面应传递关怀与专业感，避免卡通化、低龄化的视觉语言。色彩温暖但有节制，圆角柔和但不失结构感。

emoji 表情 卡通插画 几何图标 摄影级质感

2. 行动优先于记录

用户打开 APP 的第一眼应该回答三个问题：宠物状态如何？今天需要做什么？有什么重要事项？记录是行动的副产品，不是目的。

Care Home 首屏 待办高亮

3. 协作的透明感

家庭成员需要即时感知彼此的动作。谁喂了药、谁遛了狗，这些信息必须在视觉上即时呈现，不需要主动刷新或进入二级页面。

实时状态 操作者标识

4. 克制与一致性

每个新增的视觉元素都需要理由。不使用装饰性动画，不堆砌功能入口。同一类操作在不同页面中应有完全一致的交互模式。

装饰性动效 每页不同布局

5. 丝滑与响应

所有交互必须在 100ms 内给出视觉反馈。页面切换、列表滚动、按钮点击必须有精心调校的缓动曲线。卡顿是不可接受的。

60fps 动画 触觉反馈 骨架屏加载
严禁使用 Emoji
整个产品不允许出现任何 Unicode Emoji 字符。所有情绪表达、状态标识、宠物类型必须使用自定义 SVG 图标或色彩编码系统。Emoji 会严重破坏产品的专业感和设计一致性。

07. 动效系统

动效不是装饰，是交互的语言。每个动画都必须有明确的目的：引导注意力、提供反馈、解释状态变化。

缓动曲线

Spring

cubic-bezier(0.34, 1.56, 0.64, 1)

开关、弹窗、选中态

Out Expo

cubic-bezier(0.16, 1, 0.3, 1)

页面切换、列表进入

Smooth

cubic-bezier(0.4, 0, 0.2, 1)

颜色过渡、透明度

持续时间

令牌时长使用场景
--duration-instant80ms按钮按下、颜色瞬时变化
--duration-fast150ms悬停状态、微交互
--duration-normal250ms开关切换、下拉展开
--duration-slow400ms页面转场、模态框
--duration-slower600ms复杂动画、引导流程

动画模式

页面进入

.page-enter { animation: page-enter var(--duration-slow) var(--ease-out-expo) forwards; } @keyframes page-enter { from { opacity: 0; transform: translateY(12px); } to { opacity: 1; transform: translateY(0); } }

新页面从下方淡入，传达「前进」的方向感。

列表项进入

.list-item-enter { animation: list-item-enter var(--duration-normal) var(--ease-out-expo) forwards; opacity: 0; } @keyframes list-item-enter { from { opacity: 0; transform: translateX(-12px); } to { opacity: 1; transform: translateX(0); } }

列表项从左侧滑入，带有交错延迟（stagger 50ms）。

骨架屏加载

.skeleton { background: linear-gradient(90deg, ...); background-size: 200% 100%; animation: skeleton-loading 1.5s ease-in-out infinite; }

内容加载时使用，避免白屏。加载完成后内容淡入覆盖。

脉冲提醒

.pulse-ring { animation: pulse-ring 2s ease-out infinite; } @keyframes pulse-ring { 0% { transform: scale(1); opacity: 0.6; } 100% { transform: scale(1.4); opacity: 0; } }

用于紧急提醒、待办事项到期通知。

动效性能要求
所有动画必须使用 transform 和 opacity，禁止使用 width/height/top/left 等会触发重排的属性。动画帧率必须稳定在 60fps。在 prefers-reduced-motion: reduce 媒体查询下，所有动画应立即完成或禁用。

08. 图标系统

使用 SVG 图标，线条风格，2px 描边，24x24 视图框。图标必须清晰传达功能，不依赖颜色即可识别。

图标规范

线条规范

  • 描边宽度：2px
  • 端点样式：round
  • 连接样式：round
  • 视图框：24x24
  • 尺寸：24px（默认）/ 20px（紧凑）/ 16px（微小）

使用原则

  • 每个图标对应唯一语义，不重复
  • 图标 + 文字标签同时使用（底部导航除外）
  • 图标颜色跟随当前文字颜色
  • 禁用状态图标透明度降至 40%

11. 前端开发规范

CSS 架构

/* 1. 设计令牌 (tokens.css) */ :root { --color-brand-500: #F97316; --space-4: 16px; --radius-lg: 14px; /* ... */ } /* 2. 基础样式 (base.css) */ /* Reset + 字体 + 基础排版 */ /* 3. 工具类 (utilities.css) */ /* 仅在必要时使用，优先使用组件类 */ /* 4. 组件样式 (components/) */ /* button.css, input.css, card.css ... */ /* 5. 页面样式 (pages/) */ /* care-home.css, pet-detail.css ... */

性能规范

加载性能

  • 首屏加载 < 2s（3G 网络）
  • 关键 CSS 内联，非关键 CSS 异步加载
  • 图片使用 WebP 格式，懒加载
  • 字体使用系统字体栈，不加载外部字体

运行时性能

  • 动画仅使用 transform 和 opacity
  • 列表虚拟滚动（超过 50 项）
  • 图片使用 Intersection Observer 懒加载
  • 避免不必要的重渲染

无障碍规范

必须实现

  • 所有交互元素可键盘访问
  • 图片必须有 alt 文本
  • 颜色对比度 > 4.5:1（正文）
  • 表单元素必须有 label 关联
  • 支持 prefers-reduced-motion

推荐实现

  • ARIA 标签用于复杂组件
  • 焦点环清晰可见
  • 支持屏幕阅读器
  • 触摸目标最小 44x44px
